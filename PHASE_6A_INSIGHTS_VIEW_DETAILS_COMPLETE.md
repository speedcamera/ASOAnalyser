**"View details" was not interactive - it was just static text with no click handler.**

```javascript
<span className="insight-row__action">View details</span>
```

**Problems**:
- It was a `<span>`, not a `<button>`
- No `onClick` handler
- No state to track selected insight
- No drawer/modal component to show details

**Why it looked clickable**: The CSS (`.insight-row__action`) styled it with purple color and pointer cursor, but there was no actual click behavior.

## 3. Component Created: InsightDetailsDrawer

### Purpose
Single reusable side drawer component for displaying insight details across all insight types.

### Features
- ✅ Slide-in drawer from right (reuses notes-panel UI pattern)
- ✅ Shows insight type badge with tone coloring
- ✅ Displays insight summary text
- ✅ Shows context: app filter, date range, timestamp
- ✅ Placeholder message explaining future drill-down feature
- ✅ Action buttons: View Campaigns, View Keywords, Close
- ✅ Close on Escape key or overlay click
- ✅ Accessible with proper ARIA attributes

### Props
```javascript
<InsightDetailsDrawer
  open={Boolean(selectedInsight)}
  insight={selectedInsight}          // { type, text, tone }
  dateRange={dateRange}              // { startDate, endDate }
  selectedApp={selectedApp}          // { app_id, app_name, app_key }
  onClose={() => setSelectedInsight(null)}
  onViewCampaigns={() => navigate('/campaigns')}
  onViewKeywords={() => navigate('/keywords')}
/>
```

### Insight Data Structure
Current insights generated by `generateInsights()`:

```javascript
{
  type: 'Trend' | 'Alert' | 'Growth' | 'Opportunity' | 'Info',
  text: 'CPA improved by 15.3% compared to the previous period.',
  tone: 'good' | 'bad' | 'neutral'
}
```

**Note**: The drawer uses this basic structure. Future enhancements can add structured metric data (currentValue, previousValue, percentChange) without breaking the component.

## 4. Implementation Details

### A. InsightsBar Component

**Before**:
```javascript
export default function InsightsBar({ insights }) {
  // ...
  <span className="insight-row__action">View details</span>
}
```

**After**:
```javascript
export default function InsightsBar({ insights, onViewDetails }) {
  // ...
  <button
    type="button"
    className="insight-row__action"
    onClick={() => onViewDetails?.(item)}
  >
    View details
  </button>
}
```

**Changes**:
- Added `onViewDetails` prop
- Changed `<span>` to `<button>`
- Added `onClick` handler with optional chaining

## 8. Architecture Decisions

### Why Side Drawer?
- User requested "side drawer (preferred) or modal"
- Matches existing Notes panel UI pattern
- Non-blocking (can see background)
- Better for future expansion (longer content)
- Familiar interaction pattern

### Why Placeholder Message?
- User instruction: "If no detailed data exists yet: Show a placeholder explaining that detailed drill down will be available in a future update"
- Current insight objects lack structured metric data
- Avoids text parsing (fragile)
- Clear expectations for users

### Why Reusable Component?
- User requirement: "Create one reusable InsightDetails component. Do not duplicate code for different insight types."
- Easier maintenance
- Consistent UX
- Extensible (add props for future metrics)
